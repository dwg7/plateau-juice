- ステータス: 暫定(代表1タイルのみの調査。全604タイルでの集計は未実施)

## 主な知見

1. **欠損はセンチネル値で表現される**(`9999`、`-9999`、`0001`、各コードリストの「不明」)。
   空要素ではないので、単純なnull判定では欠損を拾えない。抽出時に明示的にNULL化する必要がある。
2. **欠損は全か無かに近い**。このタイルでは、用途・用途地域・階数・建築年がすべて不明の棟が393棟(44%)、
   すべて埋まっている棟が473棟(53%)。属性が部分的に欠けている棟はごく少数(25棟)。
   つまり「属性調査の範囲内/外」で二分されている可能性が高く、範囲外の棟を
   どう扱うか(除外か、別集団として扱うか)が分析設計の分かれ目になる。
3. **建築年は札幌でも公開されている**(CLAUDE.mdの「12都市のみ」に札幌が含まれることを確認)。
4. **用途地域が建物ごとに付与されている**。CLAUDE.mdの方針4(用途地域との突き合わせ)は、
   `udx/urf`の面データを空間結合しなくても、まず`districtsAndZonesType`で近似できる。
   ただし、これは都市計画決定情報そのものではないため、精査には`urf`との照合が必要。
5. 重心座標は`bldg:lod1Solid`/`lod0FootPrint`等から算出可能(幾何は出力に残さない)。

## 未確認(次のステップ)

- 604タイル全体での充実度。代表1タイルは中心部で、周辺・郊外では欠損率が異なる可能性が高い
- 属性が埋まっている範囲の地理的な広がり(欠損が空間的にどう分布するか)
- 拡張製品仕様書PDFでの各コードの定義確認(コードリストXMLで主要値は確認済み)
- 災害リスク属性の値の分布(rank・depth・scale)

## 決定

- 抽出パイプラインでは、センチネル値を明示的にNULLへ変換し、「不明」と「属性調査範囲外」を区別できる列を持つ。
- 全体解析の前に、全タイルを対象にした欠損率の集計を先に行う(`scripts/extract-attributes.py`の最初の出力)。
